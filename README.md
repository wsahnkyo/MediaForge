# MediaForge

面向 Emby 影视库的本机管理工作台。第一版使用 Python 3.11+、FastAPI、SQLAlchemy、
PostgreSQL 和 Vue 3。Vue 构建产物随 Python 提供，**运行时不需要 Node**。

## 当前范围

| 模块 | 状态 |
| --- | --- |
| 登录与后台管理 | 登录页、仪表盘、退出、修改密码、管理员/只读权限、用户创建/停用/密码重置 |
| 文件管理 | 白名单目录浏览、文件重命名、同盘/跨盘移动、确认后永久删除、预览及操作记录 |
| Hosts 管理 | 多源 HTTPS DNS、普通 DNS、TLS 测速、部分更新、备份、定时更新、IPv4/IPv6 导出 |
| 操作日志与运行日志 | PostgreSQL 保存执行结果；文件日志按日期/大小轮转，页面读取和自动追踪 |
| 元数据刮削 | 按当前影视文件夹匹配、Emby 影视与分集 NFO、本地海报和背景图、覆盖前备份 |
| 视频参数识别 | FFprobe 只读识别、数据库缓存、自动补扫、播放风险提示及跨目录对比 |
| 影视下载 | 预留网站与下载器配置、URL 解析、集数勾选及媒体目录选择界面，**未实现爬取与下载** |

首版面向 Windows 本机，不包含公网部署、多实例调度、目录递归删除或视频批量重命名整理。

### 影视下载预留

“媒体工具 → 影视下载”预留输入影视页面 URL、自动匹配网站下载器、爬取集数、勾选集数后下载的流程。
管理员可在“配置管理 → 下载器（预留）”查看网站名称、匹配域名与对应下载器的配置占位。
下载目标统一从已配置的媒体目录中选择，不接受任意磁盘路径。
目前所有相关操作均禁用；不保存网站配置、不发起网站请求、不创建下载任务，具体下载器与后端接口留待后续接入。

## Windows 启动

需要 Python 3.11+，**不要求已有 `.venv`**。以下命令均在仓库根目录执行，
其中 `python` 指你选用的 Python 解释器；安装依赖和启动服务必须使用同一个环境。
如果已经使用 Conda 或其他虚拟环境，激活后直接安装即可。

### 选择环境（虚拟环境可选）

推荐使用独立环境，避免影响其他项目。若尚无合适环境，可以创建并激活：

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

若 PowerShell 阻止运行激活脚本，无需修改执行策略；将后续命令中的 `python`
替换为 `.\.venv\Scripts\python.exe` 即可。使用其他环境时，也可以替换为该环境的解释器完整路径。
重新打开终端后，需要重新选择或激活同一个环境。

### 安装与配置

```powershell
python -m pip install -e .
if (-not (Test-Path .env)) {
    Copy-Item .env.example .env
}
```

已有 `.env` 会保留，不要覆盖。编辑其中的 PostgreSQL 连接：

```dotenv
MEDIAFORGE_DATABASE_URL=postgresql+psycopg://mediaforge:CHANGE_ME@127.0.0.1:5432/mediaforge
MEDIAFORGE_HOSTS_PATH=.\data\hosts.preview
MEDIAFORGE_HOSTS_ALLOW_SYSTEM=false
MEDIAFORGE_HOSTS_INTERVAL_SECONDS=0
```

连接串中的密码若含 `@`、`#`、`/` 等字符，需要 URL 编码，例如 `@` 写成 `%40`。
数据库本身需已存在，账号需有连接、创建 schema 和创建表的权限。推荐使用专用数据库账号。
凭据只放 `.env`，该文件已被 Git 忽略。

### 初始化与启动

```powershell
# 可单独执行；serve 启动时也会自动执行同一幂等初始化。
python -m mediaforge.cli init-db

# 交互输入密码，不回显；无默认账号密码。密码长度为 4–128 位。
python -m mediaforge.cli create-admin --username admin

# 单进程启动，同时提供 API 和构建好的 Vue 页面。
python -m mediaforge.cli serve
```

浏览器打开 **http://127.0.0.1:8765**。可用 `serve --port 8766` 修改端口。
登录后在“配置管理”页面的 **媒体目录配置** 点击 **选择文件夹**，
从磁盘列表逐级进入影视库目录，点击 **添加当前文件夹**，最后 **保存媒体目录**。
页面不提供媒体目录路径输入框，可添加多个目录，也可移除待保存目录。
目录配置存入数据库、立即生效，无需编辑 `.env` 或重启；TMDB Key、刮削器组合及正则规则也在“配置管理”维护。
忘记密码时执行：

```powershell
python -m mediaforge.cli reset-password --username admin
```

重置密码会注销该用户全部旧会话。启动只监听 `127.0.0.1`，不会自动提权。

## 数据库初始化

只使用 `mediaforge` schema，包含：

- `users`：用户名、加盐 PBKDF2-SHA256 密码摘要、角色、启用状态。
- `login_sessions`：随机会话令牌的 SHA256 摘要及到期时间；浏览器使用 HttpOnly、SameSite=Strict cookie。
- `operations`：操作人、请求摘要、running/success/partial/failed 状态、结果及错误。
- `metadata_folder_mappings`：按实际影视目录和电影 / 电视剧类型保存的 TMDB ID 关联。
- `metadata_scraper_settings`：按刮削器保存 Key、默认启用状态和组合优先级。
- `media_root_settings`：媒体目录白名单，包含明确保存的空列表。
- `filename_rename_rules`：启用状态、优先级、集号提取正则及目标模板；历史默认季号列仅保留数据库兼容，不参与执行。
- `filename_rename_directories`：实际目录的文件指纹、规则版本和最后完成检查时间。

初始化使用事务及 PostgreSQL advisory lock，重复启动不会清空数据，也不会删除其他 schema 的业务表。
这是初版建表初始化，不是后续数据库结构迁移系统；模型变更需增加显式迁移，不能依赖
`create_all` 修改已有列。
上述媒体配置表在启动时幂等创建，不修改已有表的列或业务数据。

系统配置保存在服务端 `.env`，用户、会话、操作记录、媒体目录、影视关联和刮削器配置存储于 PostgreSQL；
SQLite **仅用于离线单元测试**，应用运行不支持 SQLite。

各表按职责分离：一个用户可有多个会话，审计不能随用户或目录移除而删除；
刮削器凭据按来源保存，目录关联按实际影视位置保存，重命名检查记录不依赖 TMDB。
目前没有必须合并的重复表；不将这些不同生命周期的数据强塞进一个通用 JSON 配置表。

## 页面维护媒体目录

媒体目录通过文件夹选择器配置，浏览的是**运行 Python 服务的电脑上的目录**，
不是浏览器所在设备的目录；不会上传或读取媒体文件内容。仅管理员可浏览磁盘和文件夹。
从磁盘列表逐级进入，支持上一级，点击“添加当前文件夹”加入待保存列表；
选择器只列子文件夹，不列普通文件，链接不可进入或选择。
仅接受已存在、无符号链接 / 目录联接 / 重解析点的目录，
最多 32 个，不可重复，也不能包含本应用的日志文件或 hosts 目标。
添加或移除后重新保存即可生效；移除全部目录并保存可关闭目录访问。
移除目录只取消白名单访问，不移动或删除媒体、NFO、图片或手动 ID 关联。
暂时离线的已保存目录在重启时保留，访问时明确提示不可用。

保存后废弃旧刮削预览并重置当前页面选择；目录配置版本随页面的浏览、文件操作及关联请求提交，
旧页面使用过期的目录编号会收到刷新提示，防止配置变化后误操作另一个目录。
其他已打开的页面需刷新后继续。已有手动关联按实际路径保存，不因目录重新排序而串用。
接口为管理员专用 `PUT /api/config/media-roots`，
请求 `{"roots":["D:\\电视剧","E:\\电影"]}`，需带 `X-MediaForge-Request: 1`。
文件夹选择器使用管理员专用 `GET /api/config/media-folders` 列出磁盘，
传入 `path` 浏览对应文件夹，返回当前目录、父级和子目录；不允许相对路径或链接。
包含应用日志或 hosts 目标的目录可继续向下浏览，但不可直接选为媒体目录。
`GET /api/config` 返回当前目录及 `roots_version`。
只有数据库尚无目录记录时才兼容旧 `MEDIAFORGE_MEDIA_ROOTS`；保存空列表也不会恢复环境变量中的目录。

仪表盘统计卡片可直接跳转至文件管理、操作记录或 Hosts 页面，并支持地址栏中的页面链接。

## 文件操作边界

- 只能访问页面保存的白名单（或首次保存前的旧环境配置）指定的已有目录，使用“目录编号 + 相对路径”。
- 拒绝路径越界、Windows 设备名、ADS、符号链接、目录联接和重解析点。
- 仅操作普通文件；不递归删除目录、不自动创建目标父目录、不覆盖已有目标。
- Windows 同盘移动使用不覆盖目标的 rename；跨盘移动使用独占创建、复制完成后删除源文件。
- 首先预览，再确认执行；永久删除必须输入完整文件名，**不进入系统回收站**。
  单文件操作 API 的 `dry_run: true` 返回 `preview_id`，确认执行时必须传回同一编号。
  预览绑定操作人、目录版本、操作参数和文件状态，有效期 30 分钟、一次有效；
  不能绕过预览直接执行，修改操作参数或文件变化后须重新预览。
- 不支持只修改大小写的重命名；请先改成一个不同的临时名称。
- 文件系统与 PostgreSQL 无法共享事务：执行前先持久化 running 意图，执行后写入结果。
  若断电或数据库在末次提交时断开，操作可能已生效但记录仍为 running，请核对磁盘后处理，
  不要自动重试。跨盘移动若中途被强制终止，也可能留下部分目标文件。
- 媒体根目录应由可信本机进程管理。路径校验和进程内锁不能防御其他进程恶意并发替换目录；
  操作大文件前应暂停下载器或其他会写入同一文件的程序。

## 正则批量重命名

在“文件管理”点击 **当前文件夹 → 正则批量重命名**，或直接进入“正则重命名”页面。
**仅手动触发，只处理所选当前文件夹的直属视频，不扫描子文件夹，不启动定时任务。**
处理子目录时从“文件管理”进入该目录，再点击“当前文件夹 → 正则批量重命名”。一次最多处理 1000 个视频，目录浏览仍受 2000 项限制。
支持保存多个媒体目录；重命名时选择其中一个后，立即按已有规则验证并生成预览，
其他媒体目录不参与本次处理。第一个正确解析的规则生效，后续规则不覆盖它；
确认预览无误即可执行，只有手动修改目标名后才需要再次校验。

“配置管理 → 维护正则规则”支持添加、修改、启停、排序和删除，保存到数据库后持久生效；
“正则重命名”只负责选择目录、预览及确认，不提供规则编辑。
按顺序采用首个唯一提取且数字有效的规则；必须包含 `(?P<episode>...)`，只处理集号 1–999。
不识别季号，不根据文件夹名推断季号，没有默认季配置。目标模板默认 `{episode:02d}`，
输出 `01` / `02`，不补零用 `{episode}`，三位补零用 `{episode:03d}`。
保留原始扩展名及其大小写，例如 `.mp4`、`.avi`、`.MP4`；不修改格式、编码或视频内容。
原来保存的内置 `S{season:02d}E{episode:02d}` 模板读取时转换为集号模板，保存后持久化；
其他含季号占位符的自定义模板需要在配置页面改为仅含集号后保存。
模板不支持路径、属性访问、任意表达式或无界格式宽度。

内置规则依次识别 `S02E03`、`第04集` / `EP04`、独立数字。例如：
`Example.2020.S02E03.1080p.x264.mkv → 03.mkv`，
`Example.06.1080p.x265.mp4 → 06.mp4`。
独立数字规则示例：

```regex
(?:^|[\s._\-\[\]【】()（）])(?P<episode>\d{1,3})(?=$|[\s._\-\[\]【】()（）])
```

没有能保证所有复杂文件名都正确的单个正则，片名数字也可能恰好像集数，必须人工核对。
多处数字无法唯一确定、多集文件、链接、额外内容会跳过；年份和 `1080p` 不直接作为集数。
每个正则匹配设 50ms 超时，超时规则在本轮剩余文件中停用并明确报告，不无限等待。

选择目录自动预览，也可点击 **重新验证并预览**，不改动文件，可逐项修改目标名；修改后必须点击 **重新校验修改项**，
核对新预览后才能 **确认按预览执行**。没有需修改项时不可执行。
服务端复核非法字符、Windows 保留名、路径越界、扩展名、现有目标、批内重复和源文件状态；
冲突项全部跳过，其他正常项可继续，绝不覆盖。对应同名 NFO 和字幕一并列入预览，
组内失败时尝试安全回滚已改名项，回滚失败也逐项报告。失败后核对磁盘，不直接重复提交。
预览绑定操作人和规则版本，有效期 30 分钟、一次有效；文件或配置变化后要求重新预览。

数据库按实际目录记录当前直属文件的名称、大小、纳秒修改时间及文件标识的摘要，
并保存规则版本和检查时间，不读取视频内容。成功执行后保存改名后的指纹；
没有需修改项且无冲突时也记录已检查。下次手动触发，若无文件新增、删除或修改且规则未变化，
直接跳过。子文件夹内部变化不会触发当前目录重命名；失败或冲突不推进成功检查记录。
需要重新核对时可勾选 **即使当前目录未变化，也重新检查**；规则变更也会触发重新检查。

接口：`GET/PUT /api/renaming/rules`、`POST /api/renaming/preview`、
`POST /api/renaming/review`、`POST /api/renaming/apply`。
预览请求如 `{"root":0,"path":"","force":false,"roots_version":"..."}`，其中目录 0 就是单部影视文件夹；
复核请求包含 `preview_id` 和 `edits: [{"source":"...","new_name":"02.mp4"}]`，
执行仅提交已校验的 `preview_id`。写接口均需管理员及同源校验头。

## 视频参数识别

“视频参数识别”页面查看编码、分辨率、帧率、码率、位深、HDR、音轨和字幕，可按码率排序、
跨目录选取最多四个视频对比。需要安装 FFmpeg 工具集中的 `ffprobe`；支持 PATH，
以及 Windows 的 `%LOCALAPPDATA%\MediaForge\tools` 和 WinGet Links 目录。

服务启动、保存媒体目录后自动补扫，每 10 分钟再次检查全部已配置目录的**直属视频**，
不遍历子目录。仅处理以下扩展名，不区分大小写：
`.mkv`、`.mp4`、`.avi`、`.mov`、`.m4v`、`.ts`、`.wmv`、`.m2ts`、
`.webm`、`.flv`、`.mpg`、`.mpeg`、`.mts`。
NFO、图片、字幕、音频、临时下载文件及其他格式直接跳过，不调用 FFprobe、不写入视频元数据表。
扩展名匹配后仍需存在有效主视频轨道；空文件或损坏文件会明确记录识别失败，不生成伪元数据。

结果存入 `video_file_metadata` 表。成功且文件指纹未变化的记录复用；缺失、变化或失败的重新识别。
最近 60 秒仍有修改的文件暂缓处理。管理员也可手动补扫或重新识别。
识别只读源文件，不转码、不修改视频或 NFO，也不自动执行刮削或重命名。
工具缺失、目录离线和识别错误在页面显示，单个离线目录不阻断其他目录。

播放风险提示不是卡顿结论：需结合电视具体机型、Emby 的直放/转码状态、网络吞吐及字幕选择；
平均码率不代表峰值，按文件大小和时长估算的码率会单独标注。
接口：`GET /api/video-info/status`、`GET /api/video-info`、
`POST /api/video-info/scan`、`POST /api/video-info/scan-all`。
查询需要登录，手动扫描需要管理员及同源校验头。

## 元数据刮削

先在“配置管理”保存**单部电视剧或电影文件夹**及刮削器配置，刮削和重命名共用同一份目录列表。
在“元数据刮削”页设置电影或电视剧类型、语言后，选择媒体目录即自动使用已保存的刮削器组合生成预览，
确认后才写入；执行页不编辑目录、Key、组合顺序或 ID 关联。
刮削使用**当前选中文件夹自身的名称**匹配，只读取该层视频，将 NFO、海报和分集 NFO 直接放在同一层；
不遍历子文件夹，不要求 `Season 01`，也不自动搬动原有文件。当前目录最多列出 2000 项。

### 页面维护 Key 与组合刮削器

管理员在“配置管理 → 刮削器配置”填写 TMDB API Key（v3）或 API Read Access Token，
点击 **保存刮削器配置** 后存入数据库，立即生效，无需重启；重启后仍可使用。
输入新 Key 后保存即可替换；输入框留空保留现有值，只有勾选 **清除已保存的 Key** 再保存才会移除。
保存只校验凭据格式，实际授权失败会在调用 API 时明确报错。
配置接口只返回是否配置、来源、选择及优先级，不返回 Key；输入框不会回显已保存的值。
Key 不写入浏览器持久存储、操作日志或预览缓存。**目前数据库中明文存储 Key，未做应用层加密**，
请保护数据库访问权限和备份，不要将真实凭据提交到 Git。
没有 Key 时，点击搜索或刮削会提示先填写并保存；没有勾选来源时提示先选择刮削器。

通过勾选和“上移 / 下移”维护启用来源及顺序，保存后用于执行页；尚未保存的编辑不参与刮削。
按顺序组合：前面的来源优先，后面的只补空文本、缺失字段、空列表、分集信息和图片；
已有有效值（包括 `0` 和 `false`）保留，非空列表不拼接。嵌套对象按字段补全，分集按季集号补全。
图片从实际提供它的来源下载；某来源请求失败时显示警告，其他来源成功可保留结果，
全部失败则明确失败。所有选中来源均需事先配置凭据。
预览固定本次来源顺序与内容；修改并保存配置会使旧预览失效。
**目前实际仅接入 TMDB**，尚不能使用其他网站；已有目录手动关联和失效 ID 检查仍使用 TMDB。

兼容旧 `.env` 的 `MEDIAFORGE_TMDB_API_KEY`：只有数据库尚无 TMDB 配置记录时才回退使用它；
首次保存页面配置会将旧 Key 迁入数据库。页面清除 Key 后不会重新启用环境变量里的旧值。
老 API 客户端仍可通过请求中的 `api_key` 临时覆盖 TMDB 凭据，但页面不再采用临时传 Key 的方式。
网络请求使用固定的 TMDB HTTPS 地址、证书校验、超时和响应大小限制，不跟随重定向，
不会在 HTTP 请求日志或错误消息中暴露 Key。

`GET /api/metadata/scrapers` 登录后读取安全状态；`PUT /api/metadata/scrapers` 仅管理员可保存，
需要 `X-MediaForge-Request: 1` 请求头。保存示例：
`{"scrapers":[{"id":"tmdb","enabled":true,"priority":0,"api_key":"<你的 Key>"}]}`。
API 保留旧 Key 时省略 `api_key`；清除时传 `clear_api_key: true`，不可同时传入新 Key。
搜索与预览可传有序 `scrapers: ["tmdb"]`；省略时使用数据库默认启用顺序。

页面只选择、排序代码中已接入的刮削器，不提供通过填写网站 URL 新增刮削器的功能。
后续接入网站时，实现 `scrapers.py` 的 `ScraperClient` 协议，
并在 `metadata.py` 的 `MetadataService` 初始化注册表中添加 `ScraperDefinition`（唯一 ID、名称、客户端工厂和凭据校验器）。
重新部署后，页面自动展示新注册的来源，无需另写选择和排序界面。
由 `ScraperClient` 提供搜索、详情、分季、图片与关闭接口。适配器须将数据规范化为现有字段，
包含片名、日期、剧情、演职员、季集号和 `provider_ids`，并校验响应及图片、隐藏凭据错误；
NFO 合并与写入流程无需为网站复制一套实现。目前注册点在 `MetadataService` 初始化中。

### 预览与写入

1. 推荐文件夹命名为 `片名 (首播年份)` / `电影名 (上映年份)`，例如 `绝命毒师 (2008)`。
   自动去除年份和常见清晰度标记后搜索，只接受唯一的同名结果（包括原名），有年份时要求一致。
   无精确匹配、同名歧义或搜索有多页时跳过；不会依据热度或相似度强行选择。
   自动找不到时，可为当前选中文件夹搜索候选并关联 ID，详见下方手动流程。
2. 选择媒体目录自动生成预览；需要重试或更改类型、语言、覆盖选项后，点击“重新刮削并预览”。
   显示匹配、失败、跳过原因和待写入文件，此时不修改媒体目录，也不下载图片。
   确认后使用**这次预览确定的来源、编号和 NFO 内容**写入，不重新匹配。
   预览仅当前操作人可用，有效期 30 分钟，重启失效；最多缓存 10 份非空预览。
3. 默认保留已有 NFO / 图片，仅补齐缺失文件。需要更新时勾选“覆盖”，每个已有文件先复制为
   `原文件名.bak.<唯一编号>`，备份成功后才原子替换。备份位置在逐文件结果中显示，不自动清理。
   备份失败、图片下载失败或格式无效时不覆盖原文件；新文件不覆盖并发出现的同名目标。
4. 写入前重新校验白名单路径和目标文件状态，分集也检查对应视频；预览后发生变化则要求重新预览。
   不更改、移动或删除视频。执行失败或中断时先核对磁盘与操作记录，不盲目重复提交；
   每份预览仅允许提交写入一次。部分失败保留已成功写入的文件，结果明确列出各项错误。

### 选择当前文件夹、搜索候选并关联

1. 在“配置管理 → 刮削与关联配置”选择要关联的媒体目录及电影 / 电视剧类型，
   当前目标就是这个文件夹，搜索词自动使用其名称，不需要再选择子文件夹。
2. 保存有效 TMDB 凭据并启用 TMDB 后，点击 **调用 API 搜索**。
   搜索时从文件夹名提取片名，去掉年份、常见清晰度标记，但不按年份或同名条件过滤候选。
   可以编辑搜索词，尝试原名或其他译名；展示 ID、片名、原名、日期、简介及 TMDB 页面链接，
   支持翻页和查看原始候选 JSON。无 Key 时先选中文件夹，填写并保存 Key 后再点击搜索。
3. 自行核对后点 **使用此 ID**，再到“文件夹 → TMDB ID 关联”中核对已选目标，
   点击 **保存 / 更新关联**。也可以对已选文件夹直接填写已知 ID。未选择实际文件夹时不能保存。
   例如选择 `TV\绝命毒师 (2008)`，关联电视剧 ID `1396`，对应 TMDB `/tv/1396`。
4. 关联按**实际目录 + 影视类型**保存至数据库，重启后继续使用；
   不同父目录下的同名文件夹互不影响，媒体根目录配置顺序变化也不会串用关联。
   必须使用电影 / 剧集 ID，不是季或分集 ID。手动关联优先于自动搜索，直接按 ID 获取详情，
   不要求文件夹名及年份与上游一致；错误 ID 明确报错，不回退为另一个自动结果。
   修改 / 解除关联会使受影响的旧预览失效，需要重新预览后写入。
   解除关联仅恢复自动匹配，不删除已有媒体文件。

未匹配的预览行可点击“前往配置关联”，选中对应文件夹并搜索候选，或直接填写 ID 保存关联。
手动搜索可独立使用，无需配置媒体目录；保存关联必须选择白名单下实际存在的影视文件夹。
关联读取需登录，搜索、保存、更新、解除和清理需管理员，均记录操作日志。
搜索接口为 `POST /api/metadata/search`，JSON 示例：
`{"query":"绝命毒师","media_type":"tv","language":"zh-CN","page":1}`。
选择文件夹时额外传 `parse_folder_name: true`；返回 `results`、`page`、`total_pages`、`total_results` 等。
每个候选包含 `scraper_id`，响应还包含来源统计及 `warnings`。
`api_key` 可选，省略时使用数据库凭据（旧环境配置仅作为上述兼容回退）。
保存关联为 `POST /api/metadata/mappings`，
请求如 `{"root":0,"path":"","media_type":"tv","tmdb_id":1396}`，关联选中媒体目录本身。

### 手动检查与清理失效关联

按当前选择，**不启用定时任务**。在关联管理中提供两个按钮：
“检查失效关联（不删除）”仅报告，“检查并清理失效关联”确认后重新检查并删除确认失效的记录。
检查覆盖全部影视类型，而不仅是页面当前类型。

- 只清理已不存在的影视子文件夹，或 TMDB 详情 API **明确返回 HTTP 404** 的关联。
- 媒体根目录离线、移出白名单、权限错误、网络超时、限流、Key 错误或响应无效，均保留并报告无法验证。
  不把无法访问的根目录当作全部子文件夹已删除；不会访问白名单外的原目录。
- 使用已保存的 TMDB Key，独立于本次勾选的刮削器；无有效 Key 时仍检查目录，但保留无法验证的 ID。
  同类型同 ID 在本轮只验证一次；401 / 403 / 429 后停止继续请求其他 ID，保留其关联。
- **只删除数据库关联，不删除视频、NFO、图片或备份**。逐项显示原因及是否已清理，
  清理完如需继续刮削，应重新预览。可随时单独“解除关联”处理不再使用的记录。

对应 `POST /api/metadata/mappings/cleanup`，`{"dry_run":true}` 只检查，
`{"dry_run":false}` 检查并清理；可额外传 `api_key`，凭据不会进入操作日志。

输出示例：

```text
D:\Media\TV\绝命毒师 (2008)\
    tvshow.nfo
    poster.jpg
    fanart.jpg
    01.mkv
    01.nfo
    02.mp4
    02.nfo
D:\Media\Movies\电影名 (2020)\
    电影名 (2020).mkv
    movie.nfo
    poster.jpg
    fanart.jpg
```

NFO 使用 UTF-8 XML，包含片名、原名、简介、日期、评分、类型、演员及 TMDB / IMDb / TVDB
标识（上游提供时）。分集 NFO 使用 `episodedetails`，包含季、集、播出日期和分集 TMDB 标识，
文件名与视频一致。当前文件夹内的纯数字文件名 `01` / `1` 默认使用第 1 季，
也兼容已有 `S01E01`（含 `S00` 特别篇）文件名；不读取季文件夹。多集合并或不能识别编号的文件跳过并提示，
所有子目录均忽略，花絮文件不作为正片刮削。重命名规则独立于 TMDB 的季信息，仅处理集号。
图片保存为剧 / 电影目录下的 `poster.jpg`、`fanart.jpg`；首版不生成季级 NFO、季海报或分集缩略图。

Emby 需把影视父目录加入对应的**电影 / 电视节目**媒体库，并启用 NFO 元数据读取。
刮削完成后扫描媒体库或刷新条目；如需保留下载的本地图片，不要选择替换已有图片。
生成 NFO 不会自动修复 Emby 无法识别的目录结构。纯数字命名以同名分集 NFO 提供编号，
Emby 是否识别还取决于其版本、媒体库类型及 NFO 读取设置；多季混放且只有集号时无法判断原始季号。
参考 [Emby 电视剧命名](https://emby.media/support/articles/TV-Naming.html)、
[电影命名](https://emby.media/support/articles/Movie-Naming.html)。
预览和写入均需管理员，均记录操作人、结果及错误，不记录 TMDB 凭据。

元数据和图片来自 [The Movie Database (TMDB)](https://www.themoviedb.org/)。
本产品使用 TMDB API，但未经 TMDB 认可或认证；使用者应遵守其 API 与图片使用条款。

## Hosts 动态更新

参考 [CheckTMDB](https://github.com/cnwikee/CheckTMDB)，迁入对本机更新有效的能力：
完整媒体域名清单（去重）、Google DoH、IPv4/IPv6 结果导出及 GitHub 域名支持，
另支持直接获取 CheckTMDB 的 IPv4/IPv6 订阅。
没有迁入自动修改 README、GitHub Actions 提交推送，以及“测速全部失败仍选择首个 IP”的不安全回退。

### 本机 DNS 与 TLS 检测（默认）

1. 默认按 Google DoH → Cloudflare DoH → AliDNS DoH → 普通 DNS 的顺序查询 A/AAAA。
   每个地址族在查询失败、无记录或候选 IP 全部连接失败时切换来源；某一来源有可用 IP 后停止切换。
   HTTP 瞬时错误最多尝试 2 次，明确的 4xx（429 除外）不重复请求。
2. 拒绝非公网、特殊用途及错误地址族的候选，对 IP 的 443 端口执行 TLS 握手，并校验域名与证书。
   每个来源最多测 8 个去重候选，选取其中握手耗时最低的地址；并非扫描所有来源选全局最快 IP。
3. 不关闭证书校验；本机检测模式不直接使用远程 hosts 文件。TLS 测速不等于验证具体业务 API，
   HTTPS 查询也不保证能绕过当前网络的连接限制。
4. 更新本轮成功映射；失败的“域名 + 地址族”保留原托管区旧映射（如有），标记“未验证”并告警。
   `both` 下 A 成功、AAAA 失败时仅替换 A，保留已有 AAAA。没有任何新地址通过校验则完全不写入。
   已从配置移除的域名或地址族不再保留；托管区外始终不主动修改。
5. 只替换 `# MediaForge Hosts BEGIN` 与 `# MediaForge Hosts END` 之间的映射，
   保留托管区外的原始字节和换行；托管区外若已有同名域名，拒绝写入，避免旧条目抢先解析。
6. 内容变化时先生成唯一 `.bak.*` 备份，再使用同目录临时文件原子替换。hosts 备份不随日志清理。
   管理页显示备份路径，恢复前请停止自动更新并人工核对备份，避免覆盖其他程序的修改。

配置示例：

```dotenv
MEDIAFORGE_HOSTS_SOURCE=dns
MEDIAFORGE_DNS_SERVERS=["1.1.1.1","8.8.8.8"]
MEDIAFORGE_DNS_PROVIDERS=["google","cloudflare","alidns","dns"]
MEDIAFORGE_DNS_ATTEMPTS=2
MEDIAFORGE_HOSTS_INCLUDE_GITHUB=true
MEDIAFORGE_HOSTS_DOMAINS=["api.themoviedb.org","image.tmdb.org","api.thetvdb.com"]
MEDIAFORGE_IP_FAMILY=ipv4
MEDIAFORGE_HOSTS_INTERVAL_SECONDS=3600
MEDIAFORGE_NETWORK_TIMEOUT=3
MEDIAFORGE_PROBE_WORKERS=8
```

本机检测的 `IP_FAMILY` 可设为 `ipv4`、`ipv6`、`both`。更新间隔为 `0` 时关闭定时任务，否则最少
60 秒。服务存活时才会定时执行，启动后等待一个周期执行首次更新；不要启动多个 worker。

`HOSTS_DOMAINS` 不配置时使用 CheckTMDB 的完整去重媒体域名清单；设置后会替换该清单。
GitHub 常用域名默认额外加入，包括 `github.com`、`api.github.com`、`raw.githubusercontent.com`、
源码与发行包下载域名。在本机检测模式下，它们同样经过 DNS 查询和 TLS 校验，
**不是代理**，只帮助处理解析问题。
如不需要，设置 `MEDIAFORGE_HOSTS_INCLUDE_GITHUB=false`。

参考项目的 DNSChecker 网页接口在本次实际请求中返回 HTTP 404，未作为可用查询源迁入。
公共 DoH 服务也可能被当前网络限制；页面会保留各来源的超时、HTTP 状态和 TLS 失败原因，
不以跳过证书校验或选取未验证 IP 的方式伪装成功。

### CheckTMDB 订阅

在 Hosts 页面选择 **CheckTMDB 订阅**，可手动获取并预览或更新。每次都获取以下两个固定地址，
不受本机检测的 `IP_FAMILY` 设置影响：

- IPv4：<https://raw.githubusercontent.com/cnwikee/CheckTMDB/refs/heads/main/Tmdb_host_ipv4>
- IPv6：<https://raw.githubusercontent.com/cnwikee/CheckTMDB/refs/heads/main/Tmdb_host_ipv6>

下载仍校验 HTTPS 证书，并限制响应为 1 MiB。内容只接受有效公网 IP、对应地址族及合法域名，
仅导入 `HOSTS_DOMAINS` 和已启用 GitHub 域名允许列表中的映射。
**订阅模式不执行本机 DNS 查询或 TLS 测速**，因此格式有效不代表地址在当前网络可访问；
页面和导出文件会明确标记未做本机测速。

两个文件独立处理：一个失败时仍可更新另一个，失败地址族的旧映射保留并告警；
都没有有效新映射时不写入。有效订阅未覆盖的配置域名同样保留旧映射（如有），
包括订阅未提供的 GitHub 域名，不额外查询 DNS。写入沿用托管区、冲突检查和备份机制。

自动订阅需在 `.env` 中设置并重启服务：

```dotenv
MEDIAFORGE_HOSTS_SOURCE=checktmdb
MEDIAFORGE_HOSTS_INTERVAL_SECONDS=3600
```

默认来源仍为 `dns`，自动更新默认关闭。页面手动选择只影响本次执行，
不会改变 `.env` 中定时任务的来源。

### 执行结果与系统 hosts

每次预览/更新都保存 PostgreSQL 操作记录，并在页面显示**成功、部分成功或失败**、获取来源、
本机检测的 TLS 延迟或订阅未测速提示及失败原因。运行中的细节可在“运行日志”页面追踪，
完成后在 Hosts 页面展示本次完整结果。预览不会修改 hosts，但会写入执行日志。
页面可分别下载本轮按所选方式校验的 IPv4/IPv6 文本；不导出保留的旧映射，
不在项目目录中自动生成多余文件。

先对 `hosts.preview` 预览与更新。确需修改 Windows 系统 hosts 时，使用管理员 PowerShell，
并显式设置：

```dotenv
MEDIAFORGE_HOSTS_PATH=C:\Windows\System32\drivers\etc\hosts
MEDIAFORGE_HOSTS_ALLOW_SYSTEM=true
```

若预览正常但系统仍用旧解析，可手动执行 `Clear-DnsClientCache`。应用不会自动刷新 DNS、
提权或更改系统服务。网络超时、DNS 污染、证书错误、无写权限都会明确报错，不降级为不安全连接。
不要给 hosts 配置媒体目录内的路径。

## 日志路径、轮转与追踪

在 `.env` 中配置，修改后重启：

```dotenv
MEDIAFORGE_LOG_PATH=.\logs\mediaforge.log
MEDIAFORGE_LOG_RETENTION_DAYS=7
MEDIAFORGE_LOG_MAX_TOTAL_MB=1024
MEDIAFORGE_LOG_MAX_FILE_MB=50
```

支持绝对路径，例如 `D:\MediaForgeLogs\mediaforge.log`；目录会自动创建，需要写权限，
不能放在可操作的媒体目录内，也不能与 hosts 使用同一路径。

- 当前文件达到 **50 MiB** 或跨 UTC 日期时轮转，文件名附加时间戳和唯一标识。
- 保留 **7 天**，按文件最后写入时间判断；当前及归档文件总量最多 **1024 MiB**，
  超限从最旧的归档开始清理。异常超长的单条日志会截断，以免突破单文件上限。
- 写入日志时执行保留策略，服务空闲时每 10 分钟检查一次；服务停止期间不执行清理。
- 仅清理同目录下、符合本项目严格命名规则的归档，不删除其他文件、当前活动文件或 hosts 备份。
- 后台“运行日志”可选择读取最近 100/200/1000 行，开启追踪后每 2 秒刷新并滚动到底部。
  离开页面或退出登录后停止追踪；轮转后自动读取新的活动文件。
- 运行日志包含启动、文件/用户操作状态、hosts 各查询源及测速结果。不会记录登录密码、
  数据库连接串或会话令牌。日志读取只支持指定的活动文件，要求登录，不接受任意文件路径。

文件日志的轮转策略**不清理 PostgreSQL 中的操作审计记录**。历史审计在“操作日志”页面查看。

## 前端构建与后续拆分

仓库包含 `src\mediaforge\web` 的构建产物，因此部署时只需安装 Python 依赖。
仅在修改 Vue 源码时需要 Node（Vite 7 要求 Node 20.19+ 或 22.12+）：

```powershell
Set-Location frontend
npm ci
npm run build
```

产物输出到 `src\mediaforge\web`，Python wheel 也会包含这些文件。开发时可用 `npm run dev`，
通过 Vite 的 `/api` 代理连接正在运行的 Python 服务。前后端通过 `/api` 通信，后续可拆分部署；
拆分时需要明确配置同源代理或 CORS、HTTPS 和 cookie 策略，而不是直接暴露当前本机服务。

主要目录：

```text
frontend\src\              Vue 登录页与管理后台
src\mediaforge\app.py      API、认证依赖、静态文件、生命周期
src\mediaforge\auth.py     密码、会话和用户管理
src\mediaforge\database.py PostgreSQL 模型、初始化、操作记录
src\mediaforge\files.py    受限路径和文件操作
src\mediaforge\metadata.py 来源匹配与合并、Emby NFO、图片下载与备份写入
src\mediaforge\scrapers.py 刮削器协议、数据库凭据、选择与优先级
src\mediaforge\renaming.py 数据库正则规则、可编辑预览、目录变化检查和安全重命名
src\mediaforge\hosts.py    DNS、TLS 探测、托管区更新、调度入口
src\mediaforge\logs.py     文件日志、日期/大小轮转、保留策略与尾部读取
src\mediaforge\cli.py      启动、初始化、管理员创建与密码重置
src\mediaforge\web\        已构建的前端产物
tests\                    针对性测试，全部使用临时文件
```

API 文档为 `/docs`。浏览器登录后的同源文档可携带 cookie；写接口还需
`X-MediaForge-Request: 1` 请求头。后端不开放 CORS，避免其他网站伪造写操作。
本机 HTTP 模式 cookie 默认不带 Secure；未来 HTTPS 部署需设置
`MEDIAFORGE_COOKIE_SECURE=true`。

## 开发检查

使用与启动服务相同的 Python 环境，不限定虚拟环境名称或位置。

```powershell
python -m pip install -e ".[dev]"
python -m ruff check src tests
python -m ruff format --check src tests
python -m pytest -q
```

可选真实 PostgreSQL 测试，连接取自本地 `.env`：

```powershell
$env:MEDIAFORGE_RUN_PG_TESTS = "1"
python -m pytest -q
Remove-Item Env:\MEDIAFORGE_RUN_PG_TESTS
```

真实数据库测试为每个用例创建随机 `mediaforge_test_*` schema，只清理这些临时 schema；
不会删除项目表或已有业务表。所有文件写入及删除测试只针对系统临时目录，不触碰真实媒体或系统 hosts。
